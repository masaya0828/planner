# プランナー（PWA版）

月の目標・週の予定・今日のタスクと、24時間のルーティン時計を管理するアプリです。
データはまず端末に保存され、Googleスプレッドシートとつなぐと、スマホとPCで同じ内容を使えます。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | アプリ本体 |
| `manifest.webmanifest` | ホーム画面に追加したときの名前・アイコンの設定 |
| `sw.js` | オフラインでも開けるようにする仕組み |
| `icons/` | アプリのアイコン |
| `apps-script/Code.gs` | スプレッドシートに貼り付けるスクリプト（GitHubには置かなくても構いません） |

---

## 手順1：スプレッドシートを準備する（PCで約10分）

1. データを保存したいGoogleアカウントで Googleドライブを開き、新しいスプレッドシートを作る（名前の例：「プランナーのデータ」）
2. メニューの「拡張機能」→「Apps Script」を開く
3. 最初から書かれている内容をすべて消し、`apps-script/Code.gs` の中身を全部貼り付ける
4. 13行目の `TOKEN` の `'ここを自分だけの合言葉に書き換える'` を、自分で決めた合言葉に書き換える
   - 英数字で20文字程度の、推測されにくいものにしてください（例：`k7mR2qPx9vLw4nTz8cBd`）
   - この合言葉とURLの両方を知っている人は、データを読み書きできます。人に教えないでください
5. 保存ボタン（フロッピーのアイコン）を押す
6. 右上の「デプロイ」→「新しいデプロイ」を押し、「種類の選択」の歯車から「ウェブアプリ」を選ぶ
   - 説明：プランナー（何でも可）
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
7. 「デプロイ」を押すと、アクセスの承認を求められるので許可する
   - 「このアプリは Google で確認されていません」と出たら、「詳細」→「（プロジェクト名）に移動」→「許可」と進みます。自分で作ったスクリプトなので、この警告は通常の動作です
8. 表示された **ウェブアプリのURL**（`https://script.google.com/macros/s/…/exec`）をコピーしておく

> スクリプトをあとで書き換えたときは、「デプロイ」→「デプロイを管理」→ 鉛筆アイコン →
> バージョン「新バージョン」→「デプロイ」で反映します。URLは変わりません。

## 手順2：GitHubで公開する（PCのブラウザで約5分）

1. GitHubにログインし、右上の「＋」→「New repository」
   - Repository name：`planner`（好きな名前で可。URLの一部になります）
   - **Public** を選ぶ（無料のGitHub Pagesは公開リポジトリが対象です。データはスプレッドシート側にあるので、ここには入りません）
   - 「Create repository」を押す
2. 作成後の画面で「uploading an existing file」のリンクを押す
3. このフォルダの中身（`index.html`、`manifest.webmanifest`、`sw.js`、`README.md`、`icons` フォルダ）をまとめてドラッグして、「Commit changes」を押す
   - `icons` フォルダはフォルダごとドラッグしてください
4. リポジトリの「Settings」→ 左のメニュー「Pages」を開く
   - Source：「Deploy from a branch」
   - Branch：「main」、フォルダ「/ (root)」→「Save」
5. 数分待つと、`https://（GitHubのユーザー名）.github.io/planner/` で開けるようになります（同じ画面の上部にURLが表示されます）

## 手順3：スマホで使い始める

1. **今のデータを書き出す**：Claudeのプランナーで「月」タブを開き、一番下の「データを書き出す」→「コピー」
2. iPhoneのSafariで、手順2のURLを開く
3. 共有ボタン →「ホーム画面に追加」。以降はホーム画面のアイコンから開く
4. アプリの「設定」タブ →「データを読み込む」に貼り付け →「内容を確認」→「置き換えて読み込む」
5. 同じ「設定」タブで、手順1のURLと合言葉を入力して「接続する」
   - スプレッドシートが空なら、この端末のデータが保存されます
6. **PCや別の端末では**、URLを開いて「設定」で同じURLと合言葉を入れるだけで、スプレッドシートのデータが読み込まれます

## 使っているときのこと

- **同期のタイミング**：変更してから約1.5秒後に保存します。アプリを開いたときと、ほかのアプリから戻ってきたときに最新の内容を読み込みます。オフラインのときは端末に保存しておき、つながったら送ります
- **別の端末とぶつかったとき**：2台で同時に別々の変更をすると、「どちらを残すか」の確認が表示されます。片方を選ぶと、もう片方の変更は消えます
- **保存状態**：画面上部のタイトルの下に「同期済み 14:30」などと表示されます

## スプレッドシートを直接見る・直す

シートごとに、次の内容が入っています。直接書き換えると、次にアプリを開いたときに反映されます。

| シート | 主な列 | 書き方 |
|---|---|---|
| タスク | 内容・カテゴリ・種類・日付・完了・メモ | カテゴリは「カテゴリ」シートにある名前、種類は「タスク／実験」、完了は「済」、日付は `2026-10-12` |
| 目標 | 目標・カテゴリ・月・達成・メモ | 月は `2026-10`、達成は「済」 |
| 締め切り | 内容・日付 | 日付は `2026-10-30` |
| 振り返り | 週（月曜の日付）・メモ | |
| 日のメモ | 日付・メモ | 日付は `2026-10-12` |
| 予定 | 日付・内容・メモ | アプリで手入力した終日の予定。日付は `2026-10-12` |
| カテゴリ | 名前・色 | 色は「青／緑／橙／紫／灰／赤／青緑／黄土」。並び順はアプリの表示順です。**名前の変更はアプリで**行ってください（シートで変えると、タスク側の名前と合わなくなり「その他」扱いになります） |
| ルーティン | パターン・名前・開始・終了・色 | パターンは「平日／日曜」、時刻は `21:00` |

`meta` シートは同期の管理用なので、編集しないでください（非表示になっています）。
新しい行を手で足すときは、`id` 列は空のままで構いません。

## Googleカレンダーの予定を表示する

「今日」の画面の「この日の予定」に、Googleカレンダーの予定（終日の予定と、時刻のある予定）が読み取り専用で表示されます。

- 対象は、**スクリプトを公開したGoogleアカウント**のカレンダーのうち、Googleカレンダーの左の一覧でチェックが入っているものです。別のアカウントの予定を出したいときは、そのカレンダーをこのアカウントに共有してください
- 表示中の週の予定をまとめて読み込み、10分ごと（またはアプリを開き直したとき）に更新します。オフラインのときは最後に読み込んだ内容を表示します
- アプリからカレンダーに書き込むことはありません
- スクリプトを更新したあと最初のデプロイで、カレンダーへのアクセスの許可を求められます。「許可」を押してください（以前の許可にカレンダーは含まれていないため）

## アプリを更新するとき

GitHubのファイルを差し替えたら、`sw.js` の `const CACHE = 'planner-v1';` の数字を1つ上げてください（`planner-v2` など）。
これで、スマホに保存されている古い版が新しい版に置き換わります。

## うまくいかないとき

| 表示 | 確認すること |
|---|---|
| URLがスクリプトの公開URLではないようです | `/exec` で終わる「ウェブアプリ」のURLか。スクリプト編集画面のURLではないか |
| 合言葉がスクリプトと一致しません | 設定の合言葉と、スクリプト13行目の合言葉が同じか。スクリプトを直したなら「新バージョン」でデプロイし直したか |
| スクリプトの合言葉がまだ設定されていません | 13行目を書き換えて保存し、デプロイし直したか |
| 接続できませんでした | 通信状態。デプロイ設定の「アクセスできるユーザー」が「全員」になっているか |
